## Invariants — breaking these silently corrupts data

- **Never join closing to curation on `(date, deal_id, deal_name)` alone** → 4.01× inflation. The
  closing side must be pre-aggregated to the grain, and `seat_id` needs the `coalesce(...,'∅')`
  sentinel (38,546 curation BFM rows have NULL seat).
- **EUR = USD / rate.** `fx_rates_daily.rate` is USD per 1 EUR (≈1.16). Multiplying is the wrong
  direction (the user proposed it once). Sanity: `gross_revenue_lc / gross_revenue_eur ≈ 1.16`.
- **`range.lastN` in the dashboard counts rolled-up BUCKETS, not days** (daily only for the last 60
  days). Jobs store `window.days` as a real calendar diff, capped at 60 so preview == send.
- **The same model lives in four places** (loader, dbt, `deals_daily.sql`, `deals_daily_superset.sql`).
  Any change must land in all four or the table drifts from its documentation.
- **Scheduled-reports Drive files have exactly one writer each**: `report_jobs.json` ← Apps Script (as
  the user); `report_jobs_state.json` + `outbox/*` ← Python (service account); `outbox/acks/*` ← Apps
  Script. The SA is `fileOrganizer` on that shared drive: it can **trash**, not permanently delete
  (Drive returns 404 on delete).
- **Apps Script deployment must stay "Execute as: User accessing the web app"** — otherwise job
  ownership and per-owner sending collapse to the script owner.
- The preview/email parity between `renderEmailBody()` (JS) and `render_body()` (Python) is provable;
  re-run the README parity diff after touching either side.
- `adex_demand_new.py` reads curation labels, so **run `curation.py` first**, then adex.
- Pre-2026-07-28 duplicate grain keys in `reporting_adex_demand` (229,400, all Beachfront-sourced) are
  **accepted** by the user — sums are exact, deals are counted distinct. Do not propose a rebuild.
